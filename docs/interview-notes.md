# File Organizer Agent Interview Notes

이 문서는 `file-organizer-agent`를 면접에서 설명하기 위한 정리입니다.

## 1. 프로젝트 한 줄 설명

디렉터리 안의 파일을 확장자별 카테고리 폴더로 자동 분류하는 Python CLI 도구입니다. 실제 파일을 이동하는 도구이기 때문에 dry-run, 로그, 중복 파일명 처리, 테스트를 중심으로 안전하게 설계했습니다.

## 2. 처음 문제

- 다운로드 폴더처럼 파일이 계속 쌓이는 디렉터리는 수작업으로 정리하기 번거롭습니다.
- 자동화 스크립트가 실제 파일을 바로 이동하면 실수로 파일을 잘못 옮기거나 덮어쓸 위험이 있습니다.
- 파일 이름 충돌, 숨김 파일, 확장자가 없는 파일, 권한 문제 같은 예외 상황을 고려해야 했습니다.

## 3. 내가 한 목표

- 확장자 기준으로 파일을 `PDF`, `Images`, `Docs`, `Code`, `Data` 같은 카테고리로 분류하기
- 기본값은 dry-run으로 두어 실제 이동 전 계획을 먼저 확인하게 만들기
- `--apply` 옵션을 줬을 때만 실제 파일 이동을 수행하기
- 중복 파일명이 있을 경우 `_1`, `_2` suffix로 덮어쓰기를 방지하기
- 숨김 파일과 디렉터리는 정리 대상에서 제외하기
- 콘솔과 파일 로그를 남겨 어떤 파일이 어떻게 처리됐는지 추적하기
- pytest로 정상 케이스와 edge case를 검증하기

## 4. 구현 과정

### CLI 진입점

- `src/main.py`에서 `argparse`로 `--target`, `--apply` 옵션을 받습니다.
- `--apply`가 없으면 `dry_run=True`로 동작합니다.
- 실행 로그는 `logs/organizer.log`에 저장되고 콘솔에도 함께 출력됩니다.

관련 파일:

- `src/main.py`

### Scan -> Plan -> Execute 흐름

- `FileOrganizer.scan_and_plan()`이 대상 디렉터리를 스캔합니다.
- 파일마다 `_plan_file_move()`가 목적지 카테고리와 파일명을 계산합니다.
- `execute()`는 계획된 actions를 dry-run으로 출력하거나 실제 이동합니다.

이 구조 덕분에 실제 변경 전에 "무엇이 바뀔지"를 먼저 보여줄 수 있습니다.

관련 파일:

- `src/organizer.py`

### 카테고리 분류

- `src/config.py`의 `CATEGORIES`에 확장자별 카테고리를 정의했습니다.
- `src/utils.py`의 `get_category()`가 확장자를 소문자로 정규화한 뒤 카테고리를 찾습니다.
- 매칭되지 않는 확장자는 `Others`로 분류합니다.

관련 파일:

- `src/config.py`
- `src/utils.py`

### 중복 파일명 처리

- `get_unique_name()`은 목적지 폴더에 같은 이름의 파일이 있으면 `name_1.ext`, `name_2.ext`처럼 새 이름을 만듭니다.
- 이렇게 해서 자동 정리 과정에서 기존 파일을 덮어쓰지 않게 했습니다.

관련 파일:

- `src/utils.py`

### 숨김 파일과 디렉터리 제외

- `scan_and_plan()`은 `file_path.is_file()`인 항목만 처리합니다.
- `.DS_Store`, `.hidden.pdf`처럼 `.`으로 시작하는 숨김 파일은 제외합니다.
- 시스템 파일이나 설정 파일이 의도치 않게 이동되는 것을 막기 위한 선택입니다.

### 테스트

- `tests/test_organizer.py`에서 scan, dry-run, 실제 이동, 카테고리 디렉터리 생성, summary를 확인합니다.
- `tests/test_edge_cases.py`에서 숨김 파일, 확장자 없는 파일, 여러 점이 들어간 파일명, 특수문자/Unicode 파일명, 긴 파일명, symlink 등을 검증합니다.
- `tests/test_integration.py`, `tests/test_main.py`, `tests/test_utils.py`, `tests/test_config.py`로 CLI와 유틸리티 동작을 함께 확인합니다.

## 5. 막혔던 점

- 실제 파일을 이동하는 도구라 기본 동작을 안전하게 설계해야 했습니다.
- 같은 이름의 파일이 이미 목적지 폴더에 있을 때 덮어쓰기 위험이 있었습니다.
- 숨김 파일과 시스템 파일을 일반 문서처럼 분류하면 사용자 환경을 망칠 수 있었습니다.
- 테스트에서는 실제 파일 시스템을 다뤄야 하므로 임시 디렉터리와 샘플 파일을 잘 관리해야 했습니다.
- Windows에서는 `...` 같은 파일명을 만들 수 없고, symlink 생성에 권한이 필요해 일부 POSIX 중심 테스트가 실패했습니다.
- 로그 FileHandler를 닫지 않으면 Windows에서 임시 로그 파일 삭제가 막히는 문제가 있었습니다.

## 6. 해결 방법

- 기본 동작을 dry-run으로 두고, 사용자가 `--apply`를 명시해야 실제 이동되도록 했습니다.
- scan 단계에서 바로 이동하지 않고 actions 목록을 먼저 만들었습니다.
- 중복 파일명은 `get_unique_name()`에서 목적지 폴더를 확인해 suffix를 붙이도록 했습니다.
- 숨김 파일은 `file_path.name.startswith('.')` 조건으로 제외했습니다.
- pytest fixture로 임시 디렉터리를 만들고, 테스트가 실제 사용자 파일에 영향을 주지 않도록 했습니다.
- OS에 따라 실행할 수 없는 edge case는 `pytest.skip()`으로 분리했습니다.
- 로그 테스트에서는 생성한 FileHandler를 명시적으로 close/remove하여 임시 디렉터리 정리가 가능하도록 했습니다.

## 7. 검증

실행 명령:

```bash
pytest
pytest --cov=src --cov-report=html
```

검증 범위:

- 확장자별 카테고리 분류
- dry-run에서는 파일이 이동되지 않는지
- `--apply` 동작에서 카테고리 폴더가 생성되고 파일이 이동되는지
- 중복 파일명 처리
- 숨김 파일 제외
- 확장자 없는 파일과 unknown extension 처리
- 특수문자, Unicode, 긴 파일명 처리
- GitHub Actions에서 push와 pull request마다 pytest 실행


## 8. 면접에서 말할 포인트

### 안전한 자동화 설계

> 파일 이동은 되돌리기 어려운 작업이기 때문에 기본값을 dry-run으로 두었습니다. 사용자가 결과를 먼저 확인한 뒤 `--apply`를 명시해야 실제 변경이 일어나도록 설계했습니다.

### Plan/Execute 분리

> 스캔하면서 바로 파일을 옮기지 않고, 먼저 `(source, destination)` action 목록을 만들었습니다. 이 덕분에 실행 전 요약을 보여줄 수 있고, dry-run과 실제 실행을 같은 계획 데이터로 처리할 수 있습니다.

### 중복 파일명 처리

> 목적지에 같은 이름의 파일이 있으면 덮어쓰지 않고 `_1`, `_2` suffix를 붙입니다. 자동화 도구에서 데이터 손실을 막기 위한 핵심 안전장치입니다.

### 테스트 전략

> 단순 함수 테스트뿐 아니라 실제 임시 파일과 디렉터리를 만들어 통합 테스트를 했습니다. 파일 시스템을 다루는 프로그램이기 때문에 edge case 테스트를 많이 둔 것이 중요했습니다.

### 로그

> 자동화 도구는 나중에 "무슨 일이 일어났는지" 추적할 수 있어야 합니다. 그래서 콘솔 출력뿐 아니라 파일 로그도 남기도록 했습니다.

## 9. 다시 한다면 개선할 점

- 실행 취소 기능을 추가해 이동 기록을 기반으로 원래 위치로 되돌릴 수 있게 만들 수 있습니다.
- 사용자 설정 파일을 도입해 카테고리와 확장자를 코드 수정 없이 바꿀 수 있게 할 수 있습니다.
- `--recursive` 옵션으로 하위 폴더까지 처리할지 선택하게 만들 수 있습니다.
- 실제 이동 실패 시 일부 파일만 이동된 상태를 더 명확히 보고하는 recovery report를 추가할 수 있습니다.
- 대량 파일 처리에서는 progress 표시와 성능 측정을 추가할 수 있습니다.

## 10. 30초 답변 예시

> 파일 정리를 자동화하는 Python CLI 도구를 만들었습니다. 핵심은 단순히 파일을 옮기는 것이 아니라, 실제 파일을 건드리는 자동화에서 안전장치를 설계한 점입니다. 기본값을 dry-run으로 두고 `--apply`를 명시해야 실제 이동되게 했으며, scan과 execute를 분리해 이동 계획을 먼저 보여줍니다. 중복 파일명은 suffix를 붙여 덮어쓰기를 방지하고, 숨김 파일은 제외했습니다. pytest로 dry-run, 실제 이동, 중복 파일, 특수 파일명 같은 edge case를 검증했습니다.
